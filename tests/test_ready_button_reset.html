🧪 Test: Ready Button Reset on Player Connection

Test Overview

This test verifies that the ready button is properly reset when a player connects to the room, ensuring all players start with a clean ready status.

Issue Description

Problem: When a player connects to the room, the ready button should be reset to reflect the "not ready" state.

Expected: All players should have their ready status reset when a new player joins, and the ready button should visually reflect this reset state.

🔧 Fixes Applied

1. Server-Side Ready Status Reset

The server already resets all players' ready status when a new player joins in the resetRoom() method:

// In PokerGame.js resetRoom() method for (const player of this.players.values()) { // ... other resets ... player.ready = false; } // Clear ready status this.readyPlayers.clear(); this.allPlayersReady = false;

2. Enhanced Ready Button Text Updates

Updated the client to properly reflect ready status in button text and color:

// New updateReadyButtonText method updateReadyButtonText(isReady) { if (this.readyButtonText) { this.readyButtonText.setText('ГОТОВ'); this.readyButtonText.setFill(isReady ? '#00FF00' : '#ffffff'); // Green if ready, white if not ready } } // Updated handleReady method handleReady() { // ... existing code ... this.updateReadyButtonText(isReady); }

3. Lobby UI Updates Ready Button Text

Enhanced updateLobbyUI() to update ready button text when lobby UI is refreshed:

// In updateLobbyUI method // Update ready button text to reflect current ready status const myPlayer = this.networkManager.getMyPlayer(); if (myPlayer) { this.updateReadyButtonText(myPlayer.ready); }

In each tab, verify that the "ГОТОВ" (Ready) button shows in white color (not ready state).

Expected: Ready button should be white, indicating "not ready" state.

In multiple tabs, click the ready button to set players to ready state.

Expected: Ready button should turn green when clicked, indicating "ready" state.

Open a new browser tab and join the game with a new player name.

Expected: All existing players should see their ready status reset to "not ready" (white button).

Check all existing player tabs to verify that the ready button has been reset to white color.

Expected: All ready buttons should be white, indicating reset to "not ready" state.

Step 8: Verify Player Names Show Reset Status

Check that all player names show ❌ (not ready) instead of ✅ (ready).

Expected: All player names should show ❌ indicating they are not ready.

Step 9: Test Ready Button Functionality After Reset

Click the ready button again to verify it still works properly after the reset.

Expected: Ready button should turn green when clicked, indicating it's working correctly.

🚨 Troubleshooting

If Ready Button Doesn't Reset

Check that the server is properly calling resetRoom() when a new player joins. Look for the console logs mentioned above.

If Button Color Doesn't Change

Verify that the updateReadyButtonText() method is being called and that the button text element exists.

If Player Names Don't Show Reset Status

Check that the updatePlayerDisplay() method is being called for all players after the room reset.

✅ Success Criteria

Test Passes If:

  • All players' ready status is reset when a new player joins
  • Ready button color changes from green to white after reset
  • Player names show ❌ instead of ✅ after reset
  • Ready button remains functional after reset
  • Start game button disappears after reset (if it was visible)
  • No console errors related to ready status updates

📝 Technical Details

Server-Side Reset Process

  1. New player joins the game
  2. Server calls resetRoom() method
  3. All players' ready property is set to false
  4. readyPlayers set is cleared
  5. allPlayersReady is set to false
  6. Updated game state is broadcast to all players

Client-Side Update Process

  1. Client receives gameStateUpdate with roomReset: true
  2. updateUI() is called
  3. updateLobbyUI() is called
  4. updateReadyButtonText(myPlayer.ready) is called
  5. Button text color is updated to reflect current ready status
  6. All player displays are updated to show new ready status

Key Changes Made

  • Added updateReadyButtonText() method to centralize button text updates
  • Updated handleReady() to use the new method
  • Enhanced updateLobbyUI() to update button text on UI refresh
  • Improved visual feedback with color changes (white = not ready, green = ready)
